## Project Overview

Hood Politix (`hp_card_game`) is a real-time multiplayer card game built with Flutter and Firebase. It targets Android, iOS, Web, Windows, Linux, and macOS. The app runs in landscape-only fullscreen/immersive mode.

## Common Commands

```bash
flutter pub get          # Install dependencies
flutter run              # Run on connected device/emulator
flutter build android    # Build Android APK/AAB
flutter build web        # Build for web
flutter test             # Run all tests
flutter test test/foo_test.dart  # Run a single test file
flutter analyze          # Lint / static analysis
dart format lib/         # Format all Dart code
flutter clean            # Clean build artifacts (Gradle heap is set to 8 GB)
```

## Architecture

### Game Flow
```
Auth Gate → Login Screen → Lobby Screen → Placement Screen → Game Screen → Game Over Screen
```
- `lib/auth_gate.dart` routes between Login and Lobby based on Firebase Auth state.
- `lib/screens/placement_screen.dart` handles pre-game player positioning before the main board renders.

### State Management
- **Provider** is used at the app level (injected in `main.dart`) to supply `FirebaseService` and `PlayerHandWidgetState`.
- **`GameController`** (`lib/models/game_controller.dart`) is a per-game singleton keyed by `gameId` — use `GameController.getInstance(gameId)` rather than constructing it directly. It owns all turn-based game logic.
- **`FirebaseService`** (`lib/models/firebase_service.dart`) is a global singleton wrapping Firebase Auth, Realtime Database, and App Check.

### Firebase
- Project ID: `hood-politix-bc574`. Config is in `lib/firebase_options.dart` (auto-generated by FlutterFire CLI — regenerate with `flutterfire configure` when Firebase project settings change).
- **Realtime Database** carries live game state (player hands, turns, reactions).
- **App Check**: Debug provider on Android debug builds, PlayIntegrity on release, reCAPTCHA v3 on web.

### UI Conventions
- Widgets that need to survive navigation (e.g., player hand) are wrapped in `KeepAliveWidget` (`lib/widgets/keep_alive_widget.dart`) and use `PlayerHandWidgetState` for state persistence.
- Dialogs are pushed via a global `NavigatorKey` through `DialogManager` (`lib/widgets/dialog_manager.dart`) so game-logic code can trigger modals without widget context.
- Card drag-and-drop uses `DragTargetWidget` (`lib/widgets/drag_target_widget.dart`).

### Model Hierarchy
- `GameCard` is the base class; `ActionCard` and `NumberCard` are subclasses.
- `CardImageFactory` maps card data to asset paths under `lib/images/`.
- `Deck`, `DiscardPile`, and `DiscardStack` handle card collection logic; their widget counterparts live in `lib/widgets/`.
